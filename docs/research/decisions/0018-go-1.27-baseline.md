## Known pitfalls found

- `encoding/json` (v1) accepts duplicate object names (last wins) and replaces invalid UTF-8 silently; every reference project decodes device JSON with it (KMFDDM `fastjson`, Fleet `encoding/json`).
- The generated `schema/status` leaf types carry v1 `MarshalJSON`/`UnmarshalJSON` methods; the conformance suite compares decoded values, so it cannot notice a change in strictness.
- `go-lint.yml` set up Go twice, the second time on `stable`, so lint could run on a newer toolchain than the module declares.
- `internal/uuid` duplicated RFC 9562 version 7 generation the standard library now ships; its `Parse` and `Version` had no callers.

## What they do

- **Fleet, KMFDDM, Zentral**: lenient JSON decoders for status reports and declarations; no canonical form; tokens hashed over raw or database-normalised bytes.
- **Go 1.27**: `encoding/json` is backed by the v2 implementation but keeps v1 semantics; `encoding/json/v2` rejects duplicate names and invalid UTF-8 by default and exposes `jsontext` for token streaming.

## What we do better

1. The module declares `go 1.27.0`; every workflow and the lint job take the version from `go.mod`, nothing floats on `stable`.
2. Command and payload UUIDs come from the standard `uuid` package (`NewV7`), rendered upper case as Apple documents; `internal/uuid` is deleted.
3. JSON policy: code that decodes untrusted JSON (declarations, status reports, forwarded check-ins) uses `encoding/json/v2` with its strict defaults and `jsontext` for streaming and canonical output; existing v1 call sites stay until they are touched; the schema generator keeps emitting v1 marshal methods, which v2 honours.
4. The two behaviours are pinned by a regression test so a future toolchain change is noticed.
5. The `go fix` modernizers run as part of the bump (`atomictypes`, `embedlit`, `slicesbackward`, `unsafefuncs` and the earlier set); `go vet` now runs `stdversion` in `go test`.

## Verified by

1. `.github/workflows/*.yml` use `go-version-file: go.mod` only; `go version` in CI logs reports 1.27.
2. `mdm.TestNewCommandRoundTrip` (upper-case UUID, version 7), `profile.TestStableUUIDs`.
3. `schema/internal/conformance.TestJSONPolicy` (v2 rejects a duplicate name and invalid UTF-8; v1 keeps last-wins and replacement).
4. Same test.
5. `make lint`, `make verify` (generator output unchanged by the modernizers).

## Rejected alternatives

- Keeping `internal/uuid` for its upper-case `String`: a one-line `strings.ToUpper` at the two callers is cheaper than a package.
- Switching the generator to v2 marshal methods now: v2 honours v1 methods, so nothing is gained until phase 5's canonical JSON needs it.
- Leaving the lint job on `stable`: lint results must match the module's Go version.
