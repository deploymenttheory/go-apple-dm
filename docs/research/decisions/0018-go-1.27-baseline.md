# 0018: Go 1.27 baseline and JSON policy

## Context

The modules need a consistent toolchain and an explicit policy for JSON parsing at trust boundaries.

## Decision

Both modules declare Go 1.27.0. CI derives the toolchain version from `go.mod`. Command and profile UUIDs use the standard `uuid` package and render UUIDv7 values in uppercase.

Strict JSON paths use `encoding/json/v2` and `encoding/json/jsontext`. Generated marshaling methods retain `encoding/json` compatibility; v2 recognizes those methods. The codebase also contains v1 call sites, so strictness must be assessed at each decoding boundary.

## Rationale

A declared toolchain makes local and CI behavior reproducible. Strict decoding rejects duplicate object names and invalid UTF-8 where ambiguity would affect validation or canonicalization.

## Constraints

The minimum Go version is a build requirement. Use the checked-in module files for dependency versions. A v2 import alone does not establish strict behavior inside a custom unmarshaler.

## Verification

Conformance tests distinguish v1 and v2 JSON behavior. Command/profile tests check UUID form. Module tests and generator verification run with the declared toolchain.
